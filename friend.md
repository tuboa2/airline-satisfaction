# Closing the Kaggle S6E10 ROC-AUC Gap: An Empirical Blueprint for Data Merging and Logit-Stacking

This report provides a comprehensive analysis of high-leverage interventions to bridge the ~0.00339 ROC-AUC gap in the Kaggle Playground Series S6E10 competition. The focus is strictly on two domains: the ingestion of the original airline passenger satisfaction dataset and the development of a tail-preserving logit-space stacking strategy. These interventions are designed to directly address the identified failure points of the current rank-averaged ensemble, which degrades calibration in high-confidence prediction regions and suffers from high inter-model correlation [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1), [23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. The analysis prioritizes empirically validated implementations from previous competitions over complex theoretical frameworks, providing concrete mathematical formulations and Python implementation blueprints for immediate deployment. The ultimate objective is to guide the development process towards the 0.96155+ benchmark while mitigating the significant risk of a detrimental public-to-private leaderboard shake-up.

## Domain 1: High-Leverage Original Dataset Ingestion via Empirical Recipe

To overcome the plateau at approximately 0.9588 ROC-AUC, the first strategic lever involves exploiting the relationship between the synthetic training data and its source, the original Airline Passenger Satisfaction dataset (~130,000 rows) [[38](https://www.kaggle.com/datasets/teejmahal20/airline-passenger-satisfaction), [41](https://mavenanalytics.io/data-playground/airline-passenger-satisfaction)]. The directive is to prioritize pragmatic, empirically validated recipes proven effective in past Kaggle Playground Series competitions over theoretically complex density ratio estimation methods, which often exhibit unstable gradients on large datasets [[23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. The recommended approach is a three-part strategy comprising concatenation with an origin indicator, sample weight attenuation, and targeted leakage mining for the test set. This combination has demonstrated success in similar contexts, such as merging the original dataset in S6E8 [[32](https://www.kaggle.com/c/playground-series-s4e7/discussion/523489)] and using mean price features derived from the original dataset in another episode [[34](https://www.kaggle.com/competitions/playground-series-s5e2/discussion/565539)].

The foundational step is the physical concatenation of the original dataset with the synthetic training data. This merged dataset becomes the new training ground for all subsequent models. A critical component of this process is the creation of an `is_original` feature, where a value of 1 indicates a row is synthetic and 0 indicates it comes from the original survey [[32](https://www.kaggle.com/c/playground-series-s4e7/discussion/523489)]. This simple yet powerful feature acts as a provenance tag, allowing machine learning models like LightGBM, XGBoost, and CatBoost to learn whether a given input vector belongs to the target synthetic distribution or the auxiliary real-world distribution. By making this distinction explicit, the models are not forced to assume the distributions are identical; instead, they can learn to appropriately down-weight or ignore signals that may be artifacts of the CTGAN or TVAE generator model if those signals prove unhelpful for predicting the synthetic target variable [[5](https://www.kaggle.com/competitions/playground-series)]. This technique effectively transforms the problem from one of pure covariate shift adaptation into one where the model can actively decide how much to trust each data source. The implementation must be handled within a modular pipeline structure, likely in a dedicated module like `DataWarehouse.py`, to ensure clean data handling and reproducibility [[31](https://github.com/randxie/kaggle-pipeline)].

Once the datasets are concatenated, the next crucial step is sample weight attenuation for the original data rows. Simply merging the datasets would cause the model to be predominantly trained on the larger synthetic set, potentially drowning out valuable but smaller signal from the original data. To counteract this, original dataset rows should be assigned a lower sample weight relative to the synthetic rows during model training. The directive specifies a weight range of 0.5 to 0.75 for the original data, with synthetic data receiving a weight of 1.0 [[23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. For example, assigning a weight of 0.6 creates a deliberate imbalance that keeps the original data's influence present but secondary. This practice aligns with principles of importance weighting and adaptive boosting, where initial sample weights are adjusted to focus the learning process on difficult examples or to balance class/group representation [[37](https://pyimagesearch.com/2022/12/12/scaling-kaggle-competitions-using-xgboost-part-2/)]. While the optimal attenuation factor is problem-dependent and should be treated as a hyperparameter for tuning via cross-validation, this range represents a robust starting point based on community experience. The use of sample weights is a standard feature in gradient boosting libraries like LightGBM and XGBoost, allowing for direct implementation without requiring complex re-sampling of the dataset.

The third and most potent part of the ingestion strategy is the systematic mining for exact and near-duplicate matches between the synthetic test set (`test.csv`) and the combined `train.csv + original.csv` dataset. Since the synthetic data is generated from the original, it is highly probable that some test samples will have near-exact feature vectors present in the original dataset. Identifying these instances constitutes a form of deterministic knowledge transfer, allowing the model to leverage ground-truth labels for these leaked samples directly [[4](https://arxiv.org/html/2410.19364v1)]. The implementation requires a meticulous data alignment process. First, the entire data processing pipeline—from column selection and renaming to categorical encoding and continuous feature scaling—must be made identical for both the original and synthetic datasets [[31](https://github.com/randxie/kaggle-pipeline)]. For instance, the logic for handling `Departure Delay in Minutes` must be consistent across both sources. After alignment, a fast lookup structure, such as a Python dictionary with feature hashes as keys and corresponding labels as values, should be constructed from the aligned original dataset. Then, for each row in the synthetic test set, its feature vector is hashed and checked against the dictionary. If an exact match is found, the known label from the original dataset can be used to override the model's probabilistic prediction for that specific test row. This approach is akin to a leak-aware detection scheme proposed in academic literature, which improves performance by leveraging memorization for leaked data and generalization for non-leaked data [[4](https://arxiv.org/html/2410.19364v1)].

However, the application of this leakage-matching logic carries a significant risk: public-to-private leaderboard shake-up. Overfitting to a small slice of the test set, even if it contains leaked data, can lead to a misleadingly high public score that does not generalize [[20](https://www.kaggle.com/competitions/playground-series-s5e11/writeups/rank8-approach-trust-the-cv-score), [23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. Therefore, a strict risk mitigation protocol is paramount. The duplicate mining script must be executed only once, after all final OOF predictions have been generated and the optimal model weights determined through a trusted cross-validation loop. During the entire CV process, the test set must be treated as completely unseen. No information from the test set, including potential duplicates, should leak into the training or validation phases. This ensures that the CV score remains a reliable estimator of private leaderboard performance [[22](https://medium.com/global-maksimum-data-information-technologies/kaggle-handbook-fundamentals-to-survive-a-kaggle-shake-up-3dec0c085bc8)]. The discovery of such leaks can artificially inflate performance metrics, and competitors who rely too heavily on public LB scores often suffer from negative shake-ups when the full private test set is evaluated [[4](https://arxiv.org/html/2410.19364v1), [26](https://www.kaggle.com/code/jtrotman/meta-kaggle-competition-shake-up)]. By isolating the leakage exploitation to the final submission step, the integrity of the internal validation process is preserved. ## Domain 2: Regularized Logit-Space Stacking for Tail-Preserving Ensembles

The second strategic lever addresses the fundamental flaw in the current rank-averaging ensemble methodology. The slight drop in Public Leaderboard score from 0.95816 (OOF) to 0.95796 indicates a degradation in predictive power, specifically in the model's ability to make highly confident and correct predictions [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1)]. Rank averaging, while robust to miscalibration, discards the magnitude of prediction margins in the extreme tails of the probability distribution (>95% certainty) [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1)]. This "flattening" of the sigmoid curve erodes the very confidence intervals that are most valuable for maximizing the ROC-AUC score. To rectify this, we must transition to a more sophisticated blending mechanism: logit-space stacking. This approach preserves the margin of confidence by operating in the log-odds space, where distances between predictions are more linear and meaningful.

The core of this strategy is to transform the output probabilities of each base model from the [0, 1] probability space to the $(-\infty, +\infty)$ logit (log-odds) space. The logit function is defined as $\text{logit}(p) = \ln\left(\frac{p}{1 - p}\right)$. To ensure numerical stability and prevent taking the logarithm of zero or infinity, a small positive constant, epsilon ($\epsilon$), is added to both the numerator and denominator, resulting in the modified formula: $$\text{logit}(p) = \ln\left(\frac{p + \epsilon}{1 - p + \epsilon}\right)$$ A common choice for $\epsilon$ is 0.001, which is small enough to minimally affect well-calibrated probabilities but large enough to prevent overflow or underflow [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1)]. Once transformed, the logits from multiple models can be blended. A simple weighted sum can be used: $$z_{\text{blend}} = \sum_{i=1}^M w_i \cdot \text{logit}(p_i)$$ where $p_i$ is the OOF probability from model $i$, and $w_i$ are the blending weights. These weights can be optimized directly using a bounded optimization algorithm like Nelder-Mead or Powell, treating the OOF predictions of the base models as features and the true labels as the target for this optimization step [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1)]. The result, $z_{\text{blend}}$, is then converted back to a probability using the inverse logit (logistic) function: $p_{\text{blend}} = \frac{1}{1 + e^{-z_{\text{blend}}}}$.

While a direct logit blending is a valid improvement, a more powerful and robust approach is to employ a regularized second-stage meta-learner. Instead of manually optimizing weights, a meta-model learns the optimal combination from the data itself. For this task, a Ridge Regression or ElasticNet model is an excellent choice [[11](https://www.kaggle.com/competitions/playground-series-s6e4/writeups/error-diversity-matters-200-model-stacking-soluti), [12](https://www.kaggle.com/code/stpeteishii/introverts-ensemble-ridge-stacking)]. These models are particularly suitable because they are inherently robust to multicollinearity—a likely scenario given the high correlation between tree-based models—and provide built-in L2 (or L1+L2) regularization to prevent overfitting [[12](https://www.kaggle.com/code/stpeteishii/introverts-ensemble-ridge-stacking)]. The implementation follows the standard stacking procedure, which requires careful construction of meta-features to avoid data leakage [[14](https://datasciblog.github.io/2016/12/27/a-kagglers-guide-to-model-stacking-in-practice/)]. The process involves creating a `train_meta` matrix and a `test_meta` matrix. The `train_meta` matrix is populated with predictions from the base models on the out-of-fold (OOF) samples during k-fold cross-validation. Specifically, for each fold `k`, all base models are trained on the training portion of the fold and predict on the held-out validation portion; these predictions form a column in the `train_meta` matrix [[29](https://www.kaggle.com/c/playground-series-s6e5/writeups/5th-place-solution-a-99-model-logit-stack)]. After completing all folds, all base models are trained on the entire training set to generate predictions on the test set, which populate the `test_meta` matrix [[14](https://datasciblog.github.io/2016/12/27/a-kagglers-guide-to-model-stacking-in-practice/)].

Crucially, the feature set for the Ridge meta-learner should not be limited to just the raw probabilities or logits of the base models. To capture the dynamics of the ensemble, the meta-features must include engineered terms that describe the relationships between the models. These interaction terms allow the meta-model to understand when models agree or disagree, enabling it to weigh their outputs conditionally. The recommended feature set for the meta-learner should include:
1.  The OOF probabilities or logits from all base models ($p_{\text{lgb}}, p_{\text{xgb}}, p_{\text{cb}}, p_{\text{ft}}$).
2.  Pairwise interaction terms between models' predictions, such as $p_{\text{lgb}} \times p_{\text{xgb}}$ and $|p_{\text{lgb}} - p_{\text{xgb}}|$. These features help the meta-model identify situations where two models are strongly correlated or have divergent opinions [[14](https://datasciblog.github.io/2016/12/27/a-kagglers-guide-to-model-stacking-in-practice/)].
3.  Potentially, other engineered features derived from the residuals of the base models could further improve performance, though this adds complexity.

Before feeding these predictions into the meta-learner, it is highly advisable to apply a recalibration step. Individual models, especially boosted trees, can be overconfident, meaning a predicted probability of 0.9 might correspond to a true positive rate much lower than 0.9. This miscalibration can cause a single overconfident model to dominate the blend, dragging down the overall ensemble performance [[15](https://www.kaggle.com/competitions/playground-series-s6e8/writeups/2nd-place-solution)]. Applying a post-hoc calibration method like Isotonic Regression or Platt Scaling to the OOF predictions of each base model *before* they are used to build the meta-features can correct for this. Isotonic Regression is a non-parametric method that is generally more flexible and effective for this purpose [[15](https://www.kaggle.com/competitions/playground-series-s6e8/writeups/2nd-place-solution)]. Calibrating the inputs ensures that the "confidence" being blended is honest and comparable across all models, leading to a more stable and higher-performing ensemble.

## Risk Mitigation Framework for Public-to-Private Leaderboard Shake-Up

Implementing high-leverage techniques like original data ingestion and advanced stacking introduces inherent risks, chief among them being a significant public-to-private leaderboard shake-up [[26](https://www.kaggle.com/code/jtrotman/meta-kaggle-competition-shake-up)]. A shake-up occurs when a competitor's rank changes dramatically between the public leaderboard, which is scored on a small fraction of the test set, and the private leaderboard, which uses the remainder [[22](https://medium.com/global-maksimum-data-information-technologies/kaggle-handbook-fundamentals-to-survive-a-kaggle-shake-up-3dec0c085bc8)]. Such events are often caused by overfitting to the idiosyncrasies of the public test set or by introducing data leakage into the validation process [[23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. A robust risk mitigation framework is therefore not an optional add-on but a core requirement for any serious competitive effort. This framework rests on three pillars: adhering to the "Trust Your CV" principle, designing a leakage-proof cross-validation strategy, and carefully managing the application of data exploitation techniques.

The cornerstone of this framework is the unwavering commitment to the "Trust Your CV" principle [[19](https://www.kaggle.com/general/380742), [21](https://www.kaggle.com/general/207005)]. Cross-validation provides a more reliable and less noisy estimate of a model's generalization performance compared to a single public leaderboard score [[22](https://medium.com/global-maksimum-data-information-technologies/kaggle-handbook-fundamentals-to-survive-a-kaggle-shake-up-3dec0c085bc8)]. Relying on the public leaderboard as the primary metric for model development encourages overfitting to its specific slice of data, which may not be representative of the entire test distribution [[23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. Competitors should use their internal CV score as the guiding star for all decisions related to model architecture, feature engineering, and hyperparameter tuning. The public leaderboard should be used sparingly, primarily for confirming that the CV estimates are holding up and for a final sanity check before a major submission. The goal is to achieve a tight agreement between the CV score and the public LB score; a large discrepancy is a strong warning sign of overfitting [[22](https://medium.com/global-maksimum-data-information-technologies/kaggle-handbook-fundamentals-to-survive-a-kaggle-shake-up-3dec0c085bc8)]. In the context of this research, the OOF ROC-AUC of 0.95906 serves as the primary target metric, and any change in the stacking or ingestion strategy should be judged first and foremost by its impact on this score.

The second pillar is the design of a robust cross-validation strategy that explicitly accounts for the unique challenges of this competition, namely duplicated data. Standard K-Fold cross-validation randomly shuffles and splits the data, which can easily break up duplicate or near-duplicate samples across different folds [[22](https://medium.com/global-maksimum-data-information-technologies/kaggle-handbook-fundamentals-to-survive-a-kaggle-shake-up-3dec0c085bc8)]. This is dangerous for two reasons. First, if a duplicate sample is split between the training and validation set of a single fold, it can create a form of data leakage within that fold, artificially inflating the validation score [[3](https://www.kaggle.com/discussions/general/737609)]. Second, and more critically, if the duplicate mining strategy is applied during CV, it becomes extremely difficult to isolate the effect of the leakage, as the validation score will no longer represent a true out-of-sample performance estimate. To mitigate this, the CV strategy should be adapted. If a significant number of duplicates are identified, a GroupKFold should be employed, where each group corresponds to a unique duplicated sample. This ensures that every member of a duplicate group is kept together in the same fold, either entirely in the training set or entirely in the validation set, preventing intra-fold leakage [[22](https://medium.com/global-maksimum-data-information-technologies/kaggle-handbook-fundamentals-to-survive-a-kaggle-shake-up-3dec0c085bc8)]. Even without explicit grouping, being aware of the presence of duplicates makes any observed CV score more trustworthy, as it reflects performance on a slightly more challenging validation set that respects the underlying data structure.

The third pillar is the strict management of leakage exploitation techniques. As detailed in Domain 1, the process of finding exact matches between the test set and the original dataset is a powerful but risky tool. The cardinal rule is that the logic for identifying and leveraging these leaks must be completely segregated from the entire cross-validation and model training pipeline. The flow must be linear: 1) Train base models and generate OOF predictions using a robust CV strategy (e.g., GroupKFold) that treats the test set as entirely unseen. 2) Evaluate the ensemble's performance based on its CV score. 3) Only after the optimal model configuration and blending weights have been finalized, load the test set and run the duplicate mining script. 4) For any test rows that have a match in the original dataset, replace the model's probabilistic prediction with the known ground-truth label from the original dataset. This final step is applied only once, to the submission file, and is never used to inform any part of the training or validation process. This disciplined separation ensures that the CV score remains an unbiased estimate of generalization error, while still allowing for the maximum possible score gain from deterministic knowledge. Violating this separation is a common pitfall that leads to severe private-to-public leader board shake-ups, as the model has been indirectly trained to recognize and exploit patterns in the public test set [[4](https://arxiv.org/html/2410.19364v1), [26](https://www.kaggle.com/code/jtrotman/meta-kaggle-competition-shake-up)].

By integrating these three pillars—a steadfast commitment to CV scores, a robust CV strategy that respects data duplication, and a rigidly separated leakage exploitation phase—it is possible to safely harness the power of advanced techniques without succumbing to the perils of leaderboard overfitting. This disciplined approach transforms the modeling process from a game of chasing public scores into a rigorous scientific endeavor focused on building a model that genuinely generalizes to unseen data.

## Synthesis and Implementation Roadmap for Stage 1 Interventions

This research report has systematically deconstructed the challenge of closing the ~0.00339 ROC-AUC gap in Kaggle S6E10 by focusing on two high-leverage, computationally efficient interventions: the empirical ingestion of the original dataset (Domain 1) and the implementation of a regularized logit-space stacking strategy (Domain 2). The analysis confirms that the current rank-averaging ensemble's failure stems from its inability to preserve the margin of confidence in high-certainty predictions, compounded by the near-perfect correlation between the FT-Transformer and LightGBM, which prevents the injection of orthogonal residual variance [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1), [23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. The proposed solutions directly address these root causes.

For Domain 1, the recommended strategy is a three-pronged empirical recipe validated in prior Playground series. This involves concatenating the original ~130k row dataset with the synthetic training data, augmented with an `is_original` origin indicator feature to allow models to learn the provenance of each sample [[32](https://www.kaggle.com/c/playground-series-s4e7/discussion/523489)]. Sample weights should be attenuated for the original data (recommended range: 0.5–0.75) to maintain its signal without overwhelming the model with the larger synthetic set [[23](https://www.stimmie.dev/blog/top-ten-percent-on-kaggle)]. Most critically, an efficient duplicate mining script should be developed to identify exact matches between the synthetic test set and the original dataset, allowing for deterministic label overrides in the final submission to maximize the score on leaked data [[4](https://arxiv.org/html/2410.19364v1)]. This entire process must be implemented within a modular data handling pipeline to ensure reproducibility [[31](https://github.com/randxie/kaggle-pipeline)].

For Domain 2, the solution moves beyond simple averaging to a more sophisticated blending mechanism. The replacement of rank averaging with a regularized second-stage meta-learner, such as Ridge Regression, operating in the logit space is the central recommendation. This approach preserves the critical information about prediction confidence contained in the tails of the distribution, which rank averaging discards [[17](https://papers.ssrn.com/sol3/Delivery.cfm/6b689557-722b-4c33-ae54-76a00d689fe9-MECA.pdf?abstractid=6876276&mirid=1)]. The meta-learner is trained on a rich feature set that includes not only the calibrated logits of the base models but also their pairwise interaction and absolute difference terms, enabling the meta-model to learn conditional weighting based on model agreement [[14](https://datasciblog.github.io/2016/12/27/a-kagglers-guide-to-model-stacking-in-practice/)]. Crucially, all base model predictions should be pre-calibrated using a method like Isotonic Regression to ensure that the confidence being blended is honest and comparable across all models, preventing a single overconfident model from dominating the ensemble [[15](https://www.kaggle.com/competitions/playground-series-s6e8/writeups/2nd-place-solution)].
